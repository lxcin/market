## 2. 架构选型与理由

| 领域 | 选型 | 备选 | 选型理由 |
|---|---|---|---|
| Web | Spring Boot 3.3 + Java 17 | Spring Cloud 微服务 | 单体优先，快速闭环；一致性方案预留拆分路径 |
| ORM | MyBatis-Plus | JPA | 灵活 SQL + 逻辑删除/乐观锁/分页开箱即用 |
| 缓存/协调 | Redis + Redisson | 纯 Jedis + 自研锁 | Redisson 提供分布式锁、延时队列、阻塞队列，减少自研 |
| 可靠异步 | **Redis Stream** | RocketMQ / Kafka | 本机 Docker 下 RocketMQ broker 广播容器内网 IP（宿主机不可达），Stream 零外部依赖即可提供消费组+PEL+重试 |
| 搜索 | Elasticsearch 8 + IK + pinyin | MySQL FULLTEXT | FULLTEXT 中文效果差（且原 SQL 用 LIKE 未走索引）；ES 支持分词/相关度/聚合/高亮 |
| 指标 | Micrometer + Prometheus + Grafana | 自研埋点 | 生态标准、拉模型、与 Spring Boot 无缝 |
| 链路 | Micrometer Tracing(Brave) + Zipkin | SkyWalking | 轻量、与 Micrometer 同源、易接入 |

## 3. 请求处理链路（以"下单"为例）

```
前端 → Nginx → Spring Security(JWT 过滤器)
  → OrderController.create (@RepeatSubmit 防重)
    → OrderServiceImpl.doCreateOrder (@Observed 埋点, @Transactional)
        ├─ 校验地址 / 购物车选中项
        ├─ 计算金额 / 优惠券预览
        ├─ 写 t_order + t_order_item
        ├─ inventory.reserveStock (乐观锁 CAS 预占)
        ├─ 写 t_outbox(ORDER_CREATED)   ← 与订单同事务
        └─ orderDelayQueue.scheduleCancel (Redisson 延时队列)
    ← 返回 OrderVO
  → OutboxDispatcher 异步消费 ORDER_CREATED → 累加销量 + 刷新 ES
```

## 5. 关键设计原则

1. **热点路径不落库**：秒杀扣减走 Redis Lua；购物车读走 Redis。
2. **最终一致**：跨"业务数据 + 副作用"用 Outbox；跨时间（超时关单）用延时队列；跨系统用对账。
3. **幂等优先**：状态变更用 CAS（`WHERE status=?`），消费用唯一键，回调用业务单号。
4. **降级兜底**：搜索 ES 失败降级 MySQL；关单延时队列 + 低频兜底扫描。
5. **可观测先行**：关键业务事件有指标，异步链路有 traceId。
