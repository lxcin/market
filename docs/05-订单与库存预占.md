# 05 · 订单与库存预占

## 1. 订单状态机
新增 `OrderStatus` 枚举，显式定义状态与允许流转，避免非法状态：

```
PENDING(0 待支付) → PAID(1 已支付) | CANCELLED(4 已取消)
PAID(1)           → SHIPPED(2 已发货) | REFUNDED(5 已退款)
SHIPPED(2)        → COMPLETED(3 已完成) | REFUNDED(5)
COMPLETED/CANCELLED/REFUNDED = 终态
```
- `getStatusDesc` 统一走枚举；`AdminOrderController` 改状态前 `canTransitionTo` 校验，非法直接拒绝。
- 业务侧状态变更仍以 **CAS SQL** 为最终守卫（`WHERE status=0`），枚举用于校验与文档。

## 2. 库存预占模型（核心）
### 背景
原实现"下单即扣减 `stock`"，未支付订单长期占用可用库存，且 `t_inventory.locked_stock` 从未使用。

### 现方案：预占 → 提交 → 释放
| 阶段 | 操作 | SQL 语义 |
|---|---|---|
| 下单 | `reserveStock` | `stock-=q, locked_stock+=q, version+=1`（CAS：`stock>=q AND version=?`） |
| 支付成功 | `commitStock` | `locked_stock-=q`（可用库存在预占时已扣 → 实售） |
| 取消/超时 | `releaseStock` | `stock+=q, locked_stock-=q` |
| 退款 | `increaseStock` | `stock+=q`（已提交，回补可用） |

- 并发安全：`reserveStock` 用**版本号乐观锁 + 重试 3 次**。
- **不变量**：`locked_stock == Σ(待支付订单明细数量)`（对账依据）。

## 3. 下单主流程（`OrderServiceImpl.doCreateOrder`，@Transactional）
1. 幂等键查重：`t_order.idempotent_key` 唯一，命中直接返回已有订单。
2. 校验收货地址归属；取购物车选中项（或直接购买）。
3. 计算总额；如有优惠券则 `previewDiscount` 得折扣与实付。
4. 写 `t_order`（含收货人/地址快照）+ `t_order_item`（书名/封面/单价快照）。
5. 逐项 `reserveStock`（库存不足抛异常 → 整体回滚）。
6. 写 `t_outbox(ORDER_CREATED, {items})`（**与订单同一事务**）。
7. `orderDelayQueue.scheduleCancel(orderId)` 投递延时关单。
   > 取消购物车已选项、核销优惠券在同一事务内完成。

## 4. 秒杀聚合链路
```java
createOrder(@Observed)
  → doCreateOrder (@Transactional)  // 订单+明细+预占+outbox 原子
  → OutboxDispatcher (异步)          // 累加销量 + 刷新 ES
  → OrderTimeoutConsumer (延时)      // 到期关单：CAS + releaseStock + refundCoupon
```

## 5. 幂等与并发要点
- **下单幂等**：`idempotent_key` 唯一键。
- **状态迁移幂等**：`payOrderCas` / `cancelOrderCas` / `markPaid` 均 `WHERE status=?`。
- **超卖防护**：预占 CAS（`stock>=q`）+ 版本号。

## 6. 验证
- 下单前 `stock=500/locked=0` → 下单后 `stock=498/locked=2` → 支付后 `stock=498/locked=0`。
- 订单 12（未支付）到期自动 `status=4`，`stock` 由 399 回到 400、`locked` 归 0。
- 非法流转 `已取消→已发货` 被拒。
