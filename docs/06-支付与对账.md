# 06 · 支付与对账

## 1. 数据模型
| 表 | 作用 | 关键字段 |
|---|---|---|
| `t_payment` | 支付流水 | payment_no(唯一)、order_id、amount、status(0待/1成功/2失败/3关闭/4退款)、trade_no(唯一)、notify_time |
| `t_refund` | 退款流水 | refund_no(唯一)、payment_no、amount、status(0处理中/1成功/2失败)、refund_trade_no |
| `t_gateway_bill` | 网关对账单 | payment_no、trade_no、amount、status(SUCCESS/REFUND) |

## 2. 模拟支付网关（`MockPayGatewayService`）
**选型**：自研"模拟网关"，行为对齐真实网关（下单→异步回调→验签→记账），便于本地无第三方联调。

- 启动生成 **RSA 密钥对**；网关用私钥 **SHA256withRSA 签名**，平台用公钥 **验签**（贴合"平台仅持公钥"）。
- `paySuccess` / `refundSuccess`：写 `t_gateway_bill`，把 `{业务单号, tradeNo, amount, status, timestamp, sign}` **异步回调**平台（独立线程池，`pay-callback-*`）。
- 回调通过 Boot 构建的 **RestTemplateBuilder** 发出（自带 Observation → client span，链路可串）。

## 3. 统一下单与支付
- `POST /api/payment/create/{orderId}`（`@RepeatSubmit`）：校验归属/状态/超时，**幂等**复用待支付支付单，返回 `{paymentNo, amount, channel, sandboxUrl}`。
- 沙箱支付：`POST /api/payment/sandbox/{paymentNo}/pay` → 触发网关回调（异步，调用方立即返回）。
- 前端收银台：提交后**轮询** `GET /payment/{orderId}` 直到终态。

## 4. 回调处理（`handleNotify`，验签 + 三重核对 + 幂等）
1. **验签**：`PaySignUtil.verify(canonical(params), sign, 公钥)`，失败返回 `fail`。
2. **金额核对**：回调金额 == 支付单金额 == 订单应付金额，任一不符记 `【对账告警】` 并 `fail`。
3. **幂等记账**：`UPDATE t_payment SET status=1,trade_no=? WHERE payment_no=? AND status=0`；重复回调走"已成功"幂等分支返回 success。
4. **改订单**：`payOrderCas(order_id)`（`WHERE status=0`）。
5. **库存提交**：逐项 `commitStock`（锁定转已售）。
6. **发事件**：写 `t_outbox(PAYMENT_SUCCESS)`（与状态变更同事务）。
7. 返回**纯文本 `success`/`fail`**（网关约定）。

## 5. 退款
- `POST /api/payment/refund/order/{orderId}`：校验归属 + 订单 `status=1`；幂等复用退款单；调网关退款（异步回调）。
- `handleRefundNotify`：验签 + 金额核对 + CAS `markSuccess` → 支付单转 4、订单转 5、**回补库存**。

## 6. 对账（`PaymentReconcileTask` + 手动接口）
- 定时（每日 02:00）与手动 `GET /api/payment/reconcile?days=`：比对本地成功支付与 `t_gateway_bill`，识别：
  - `localOnly`（本地成功、网关无）→ 告警
  - `amountMismatch`（金额不符）→ 告警
  - `gatewayOnly`（网关成功、本地掉单）→ **自动补偿**（补记已支付 + 订单转已支付）
- 秒杀侧另有 Redis 库存对账；库存/优惠券对账见文档 08。

## 7. 异步与一致性
- 回调线程池 `payCallbackExecutor` 挂 **`ContextPropagatingTaskDecorator`** → TraceContext/MDC 传播，回调与发起请求**同一条 trace**；出站 RestTemplate 注入 `traceparent` → `/notify` 续接同一 trace（12 个 span）。

## 8. 验证
- 无签名/错误金额回调 → `fail`；正确回调 → 支付单=1、订单=1。
- sandbox 请求 → 出站 client span → notify 入站 → `handle-notify` 业务 span，**同 trace**。
- 退款：退款单=1、支付单=4、订单=5、库存回补。
- 注入"网关有单本地无"→ 对账 `repaired=1`，订单转已支付。
