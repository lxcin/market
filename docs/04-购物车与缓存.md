# 04 · 购物车与缓存

## 一、购物车（Redis 主存储 + Stream 可靠落库）

### 1. 数据模型
- Redis Hash：`cart:{userId}`，field=`bookId`，value=`CartItemVO`(JSON)。
- DB 备份：`t_cart`（user_id + book_id 唯一），用于 Redis 异常/淘汰后恢复。

### 2. 为什么改（原方案失效）
原实现用 `RocketMQTemplate` 异步落库，但 RocketMQ 自动装配被排除（broker 在本机 Docker 下广播容器内网 IP，宿主机不可达）→ `rocketMQTemplate` 为 null，**购物车从不落库**，`syncFromDb` 也无人调用。

### 3. 现方案：Redis Stream 可靠异步
- `CartServiceImpl` 所有变更（加购/改量/勾选/删除）向 **`cart:stream`** 投递事件：
  `{userId, bookId, quantity, checked, op=UPSERT|DELETE}`。
- `CartPersistWorker`：消费组 `cart-group`，**阻塞读取**（`XREADGROUP ... BLOCK 2s`，无空转），幂等 upsert/delete `t_cart`，`XACK`；失败留 PEL，`XAUTOCLAIM` 重试。
- 读：`list()` 命中 Redis；Redis 空时 `syncFromDb` 从 DB 备份恢复。

### 4. 关键点
- 单 Stream + 单消费组 → **有序**，避免"旧 UPSERT 覆盖新 DELETE"。
- 删除也走事件（而非直连 DB），保证与 UPSERT 的顺序一致。
- 价格在读时以 DB 最新价校准。

### 5. 验证
- 加购 book6×3 → `t_cart` 出现 `(user=2,book=6,qty=3,checked=1)`，`cart:stream pending=0`；删除 → 该行清零。

## 二、缓存三件套

### 1. 选型
- **两级缓存**：L1 进程内 `LocalCache`（TTL+容量） + L2 Redis（`RedisTemplate`，GenericJackson2Json 含 JavaTimeModule）。
- **统一读取器** `CacheHelper.getOrLoad(key, ttl, loader)` 一次性解决穿透/击穿/雪崩，业务无感知。

### 2. 三个问题与对策
| 问题 | 对策 | 实现 |
|---|---|---|
| 穿透（查不存在的 key） | 布隆过滤器 + 空值哨兵 | `RedisBloomFilter`（Redis 位图，4 哈希，启动预热商品 id）；`CacheHelper` 空结果缓存 `__NULL__`（短 TTL 60s） |
| 击穿（热点 key 过期瞬间） | 分布式互斥锁重建 | `RLock cache:rebuild:{key}`，抢到锁的线程查库回填，其余自旋重读 |
| 雪崩（大量 key 同时过期） | 随机 TTL + 两级缓存 | TTL × random(0.8~1.2)；L1 摊薄 Redis 压力 |

### 3. RedisConfig
`GenericJackson2JsonRedisSerializer` 需显式注册 **JavaTimeModule** 并开启默认类型信息，否则含 `LocalDateTime` 的实体序列化失败（已修）。

### 4. 接入点与失效
- 接入：商品详情/热榜/高分榜（`BookServiceImpl`）、分类树（`CategoryServiceImpl`）。
- 失效：Admin 商品写操作 `evictBook`（详情 + 模式清 hot/top）、分类写操作 `evictTree`。
- 命中率指标：`cache_access_total{result=hit_local|hit_redis|miss}`。

### 5. 关键 Redis 键
`cache:book:{id}`、`cache:book:hot:{n}`、`cache:book:top:{n}`、`cache:category:tree`、`bloom:book:ids`、`cache:rebuild:{key}`(锁)。

### 6. 验证
- 不存在的 id → 布隆拦截，未查库未缓存；
- TTL 抖动（600→508s）、写后缓存失效（`cache:book:1` 1→0）。
