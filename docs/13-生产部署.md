# 13 · 生产部署（单服务器 + Docker Compose + GHCR）

## 1. 部署拓扑
```
Internet ──:80──> market-web(nginx: 静态前端 + /api 反向代理)
                       └──> market-server:8080 ──> mysql / redis / elasticsearch（仅内网）
```
- 对外只暴露 **80**（`market-web`）；`mysql/redis/es/market-server` 都在 Compose 内网。
- 镜像通过 **GitHub Actions 构建并推送到 GHCR**，服务器只负责拉取运行。

## 2. CI（GitHub Actions）
`.github/workflows/deploy.yml`：push 到 `main` 时自动：
1. `mvn package` 构建后端 jar；
2. 构建并推送三个镜像到 GHCR：
   - `ghcr.io/<owner>/market-server:latest`
   - `ghcr.io/<owner>/market-web:latest`
   - `ghcr.io/<owner>/market-es:8.11.0`（含 IK + pinyin 插件）

## 3. 服务器准备
```bash
# 1) 安装 Docker 与 Compose（示例：Ubuntu）
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER   # 重新登录生效

# 2) Elasticsearch 需要（否则容器会启动失败）
sudo sysctl -w vm.max_map_count=262144
echo "vm.max_map_count=262144" | sudo tee -a /etc/sysctl.conf

# 3) 放行 80 端口（云安全组 / 防火墙）
```

## 4. 拉取与启动
```bash
# 代码/编排文件（二选一）
git clone https://github.com/lxcin/market.git && cd market/docker
# 或：仅上传 docker/ 目录

# 配置密钥
cp .env.prod.example .env
vim .env      # 填 MYSQL_ROOT_PASSWORD / DB_PASSWORD / REDIS_PASSWORD / JWT_SECRET

# 拉取镜像（GHCR 包若为私有，需先登录）
#   在 GitHub → Settings → Developer settings → PATs 生成带 read:packages 的 token
docker login ghcr.io -u lxcin

# 启动
docker compose -f docker-compose.prod.yml pull
docker compose -f docker-compose.prod.yml up -d
```

访问：`http://<服务器IP>/` ；管理员默认 `admin / admin123`（**上线后请立即改密码**）。

> 让 GHCR 包公开可省去 `docker login`：GitHub → 你的账号 → Packages → 每个包 → Package settings → Change visibility → Public。

## 5. 首次数据库初始化
- 新数据卷首次启动 `mysql` 时会自动执行 `docker/mysql/init.sql`（建表 + 种子数据 + 管理员）。
- **已有数据卷**不会重跑；后续新增的表需手动执行（或重建卷）。

## 6. 更新发布
```bash
cd market/docker
docker compose -f docker-compose.prod.yml pull
docker compose -f docker-compose.prod.yml up -d
# 回滚到指定版本：
#   .env 里 IMAGE_TAG=<旧tag>，再 pull && up -d
```

## 7. 备份与恢复
```bash
# MySQL 逻辑备份
docker exec market-mysql mysqldump -uroot -p"$DB_PASSWORD" market > backup_$(date +%F).sql
# Redis：AOF 在 redis-data 卷（/data）
# ES：使用 snapshot 仓库（首次需在 ES 注册 path.repo）
```
建议配置为定时任务并异地保存。

## 8. 常见问题
| 现象 | 原因 / 处理 |
|---|---|
| ES 容器反复重启 | 宿主 `vm.max_map_count` 未设置；或内存不足（调 `ES_JAVA_OPTS`） |
| `pull` 报 403/unauthorized | GHCR 包私有且未 `docker login`，或复用 token 权限不足 |
| 页面能开但接口 502 | `market-server` 未就绪（看 `docker logs market-server`），或健康依赖未通过 |
| MySQL 乱码 | 容器已带 utf8mb4；如旧卷异常，重建卷 |
| 时间相差 8 小时 | 已通过 `TZ=Asia/Shanghai` + `--default-time-zone=+08:00` 修正 |

## 9. 后续增强（按需）
- **HTTPS**：加一个 Caddy 容器（自动 Let's Encrypt）或宿主 Nginx + certbot；有域名后即可启用。
- **可观测**：把 `docker-compose.observability.yml`（Prometheus/Grafana/Zipkin/Alertmanager）部署到服务器或内网，并接入告警通知。
- **多实例**：`market-server` 无状态，可水平扩容 + 负载均衡；会话在 JWT/Redis。
- **数据库高可用**：迁移到云 RDS 或 MySQL 主从。
- **日志**：接 Loki/ELK 集中收集。
