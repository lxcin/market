# 12 · 存储设计（MySQL 与 Redis 分工）

## 0. 总原则
- **MySQL = Source of Truth**：所有需要**持久、事务、关系、复杂查询、对账**的数据都落 MySQL。
- **Redis = 快、原子、临时、协调**：热点读缓存、高并发原子扣减、可靠队列、分布式锁、限流、TTL 过期数据。
- 任何"Redis 里有的"，最终都能在 MySQL 找到（或可重算），**Redis 不是唯一存储**。

## 一、MySQL 表（15 张）

### 用户域
**`t_user`** — 用户
| 列 | 说明 |
|---|---|
| id PK | |
| username UNIQUE | 登录名 |
| password | BCrypt 哈希 |
| phone / email | 手机/邮箱（idx） |
| avatar / role(USER/ADMIN) / status | |
| created_at/updated_at/deleted | 逻辑删除 |

**`t_address`** — 收货地址
`id, user_id, receiver_name, phone, province, city, district, detail, is_default, created_at, updated_at`

### 商品域
**`t_category`** — 分类（树）
`id, parent_id(0=顶级), name, sort, created_at, updated_at, deleted`

**`t_book`** — 图书
`id, title, author, isbn, publisher, publish_date, category_id, price, rate, cover_image, description, detail, sales, status(1在售), created_at, updated_at, deleted`
（索引：category_id、author、status）

**`t_inventory`** — 库存（与商品分离）
`id, book_id UNIQUE, stock(可用), locked_stock(预占), version(乐观锁), updated_at`

### 购物车
**`t_cart`** — 购物车备份（主数据在 Redis）
`id, user_id, book_id, quantity, checked, created_at, updated_at` ，UNIQUE(user_id, book_id)

### 优惠券
**`t_coupon_template`** — 券模板
`id, name, type(1满减/2折扣/3直减), threshold_amount, discount_amount, discount_rate, total_count, remaining_count, per_user_limit, start_time, end_time, status, created_at, updated_at, deleted`

**`t_user_coupon`** — 用户券
`id, user_id, coupon_template_id, status(0未用/1已用/2过期), order_id, used_time, created_at`
约束：UNIQUE(user_id, coupon_template_id)、UNIQUE(order_id)

### 订单域
**`t_order`** — 订单
`id, order_no UNIQUE, user_id, total_amount, discount_amount, pay_amount, status, coupon_id, address_id, receiver_name/phone/address(快照), pay_time, idempotent_key UNIQUE(幂等), created_at, updated_at, deleted`

**`t_order_item`** — 订单明细（快照）
`id, order_id, book_id, book_title, book_cover, quantity, price`

### 支付域
**`t_payment`** — 支付流水
`id, payment_no UNIQUE, order_id, order_no, user_id, channel, amount, status(0待/1成功/2失败/3关闭/4退款), trade_no UNIQUE, notify_time, created_at, updated_at`

**`t_refund`** — 退款流水
`id, refund_no UNIQUE, payment_no, order_id, user_id, amount, reason, status(0处理中/1成功/2失败), refund_trade_no, created_at, updated_at`

**`t_gateway_bill`** — 网关对账单（模拟）
`id, payment_no, trade_no, amount, status(SUCCESS/REFUND), bill_time`

### 一致性 / 其它
**`t_outbox`** — 本地消息表
`id, event_type, aggregate_type, aggregate_id, payload(JSON), status(0待/1已/2失败), retry_count, last_error, created_at, updated_at`

**`t_comment`** — 评论
`id, book_id, user_id, content, rate(1-5), parent_id, created_at, updated_at, deleted`

## 二、Redis 用途（键 / 结构 / TTL）

| 键 | 结构 | 用途 | TTL | 为什么用 Redis |
|---|---|---|---|---|
| `cart:{userId}` | Hash | 购物车主存储 | 长（可无） | 高频读写、低延迟，DB 仅备份 |
| `cart:stream` | Stream(组 cart-group) | 购物车落库队列 | 持久 | 可靠异步 + 消费组 + PEL |
| `seckill:stock:{id}` | String | 秒杀库存 | 活动期 | Lua 原子 DECR，抗并发热点 |
| `seckill:user:{id}:{uid}` | String | 用户已领数 | 7 天 | 限领判断，原子 INCR |
| `seckill:limit:{uid}` | String | 秒杀限流 | 10s | 防刷（INCR+EXPIRE） |
| `seckill:stream` | Stream(组 seckill-group) | 秒杀落库队列 | 持久 | 可靠异步落库 |
| `order:timeout:queue`(+Redisson ZSet) | Queue/ZSet | 延时关单 | 到期 | 精确延时消息，重启不丢 |
| `bloom:book:ids` | Bitmap | 布隆防穿透 | 长 | 位图省内存，O(1) 判存在 |
| `cache:book:{id}` 等 | String(JSON) | 商品/分类缓存 L2 | 抖动 10min/60s/30min | 热点读降 DB 压力 |
| `cache:rebuild:{key}` | Redisson Lock | 缓存重建互斥 | 短 | 防击穿 |
| `auth:captcha:{id}` | String | 图形验证码 | 5min | 一次性、自动过期 |
| `auth:sms:{phone}` / `auth:sms:limit:{phone}` | String | 短信码 / 防刷 | 5min / 60s | 自动过期 |
| `auth:login:fail:{u}` / `auth:login:lock:{u}` | String | 登录失败计数/锁定 | 15min | 计数 + 自动解锁 |
| `auth:blacklist:{jti}` | String | JWT 黑名单 | 剩余有效期 | 登出即时失效 + 自动清理 |
| `repeat:{uid}:{method}` | String | 防重提交 | N 秒 | SETNX 跨实例 |

## 三、为什么这样分工（决策依据）

| 需求 | 用 MySQL | 用 Redis |
|---|---|---|
| 持久化/不能丢 | ✅ 订单、支付、库存、券 | ❌（Redis 可 flush/淘汰） |
| 事务/多表原子 | ✅ `@Transactional` + 唯一键 | 仅单命令原子，跨 key 需 Lua |
| 关系/复杂查询/分页 | ✅ JOIN、聚合、LIKE、分页 | ❌ 不适合 |
| 对账/审计 | ✅ 唯一可信来源 | Redis 是派生，可按 DB 修正 |
| 高并发热点（秒杀/购物车） | ❌ 行锁/DB 成瓶颈 | ✅ 内存 + 原子命令 |
| 低延迟 | 相对慢 | ✅ 亚毫秒 |
| 自动过期/临时数据 | ❌ | ✅ TTL 天然清理 |
| 队列/锁/限流/位图 | ❌ | ✅ Stream/ZSet/Bitmap/INCR |

**数据流向**：写走 MySQL（事务），Redis 做缓存/闸门/队列；Redis 数据要么有 DB 备份（购物车/秒杀券），要么可重算（缓存/预扣库存），**Redis 出问题不丢核心数据**。

## 四、一致性关系（谁是真源）
| 数据 | 真源 | Redis 角色 | 兜底 |
|---|---|---|---|
| 商品/分类 | MySQL | 缓存 | 缓存失效回源 |
| 库存 | MySQL(`stock/locked_stock`) | 秒杀预扣副本 | 对账按 DB 修正 |
| 购物车 | Redis | 主存储 | `syncFromDb` 从 `t_cart` 恢复 |
| 优惠券 | MySQL(`t_user_coupon`) | 秒杀库存副本 | 对账校验 |
| 订单/支付 | MySQL | 无 | 对账补偿 |
