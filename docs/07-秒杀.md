# 07 · 秒杀（高并发）

## 1. 目标与约束
- 大并发抢券**不超卖**；热路径尽量不落库；异步落库**可靠、幂等**；可对账。

## 2. 选型
原实现为"Redisson 分布式锁 + 查库限领 + DB 扣减"，全部串行在数据库层，QPS 低。

现方案：**Redis 原子预扣（Lua）+ Redis Stream 可靠队列 + 幂等落库 + 对账**。
（弃用 RocketMQ：本机 Docker 下 broker 广播容器内网 IP，宿主机不可达；Stream 零依赖提供消费组/PEL/重试。）

## 3. 原子预扣（Lua）
`resources/lua/seckill_claim.lua`（单次 EVAL 内原子完成）：
```
库存<=0 → -1(抢完)；用户已领数>=限领 → -2(超限)；未预热 → -3
否则：DECR 库存 + INCR 用户计数 + EXPIRE + XADD 入队，返回 1
```
- KEYS：`seckill:stock:{id}`、`seckill:user:{id}:{uid}`、`seckill:stream`。
- 消息字段：`userId,templateId,requestId,traceId,spanId`（后两者用于异步链路续接）。

## 4. 领取流程（`SeckillServiceImpl.claim`）
1. 校验模板状态/时间；**单用户限流**（`seckill:limit:{uid}`，10s 内 >20 拒绝）。
2. 未预热则懒加载库存。
3. 执行 Lua；按返回码抛"已抢完/超限/未就绪"。
4. 成功 → 返回 `{requestId, status:ACCEPTED}`（**立即返回**，返回后异步落库）。

## 5. 异步落库（`SeckillClaimWorker`）
- Redis Stream 消费组 `seckill-group`，`XREADGROUP` 消费 → **幂等**写 `t_user_coupon`（唯一键 `uk_user_template` 冲突即幂等）+ CAS 扣 `remaining_count` → `XACK`。
- 失败留 PEL，`retryPending` 用 `XAUTOCLAIM` 重试。
- **链路续接**：用消息里的 `traceId/spanId` 构造 `TraceContext`，`seckill.persist` 子 span 归入原领取请求同一条 trace；MDC 注入 traceId 使异步日志可关联。

## 6. 对账与预热
- `SeckillWarmupRunner` 启动预热进行中模板库存到 `seckill:stock`。
- `SeckillReconcileTask`：校验 `total/remaining/issued` 与 Redis 库存；无待处理消息时按 DB 修正 Redis。
- `GET /api/coupon/seckill/stock/{id}`、`POST /api/admin/coupon/{id}/warmup`。

## 7. 压测（`loadtest/seckill-loadtest.mjs`）
Node 原生 http + 连接池，自建用户并发抢券，统计 QPS/P50/P95/P99。

| 轮次 | 用户 | 并发 | 库存 | 成功 | 失败 | 耗时 | QPS | P50 | P95 | P99 |
|---|---|---|---|---|---|---|---|---|---|---|
| 1 | 300 | 300 | 100 | **100** | 200 | 547ms | 548 | 374ms | 532ms | 538ms |
| 2 | 1000 | 500 | 200 | **200** | 800 | 1801ms | 555 | 777ms | 985ms | 1025ms |

**结论**：成功数恰等于库存 → **零超卖**；`t_user_coupon=200`、`remaining=0`、Redis `stock=0`、`stream pending=0` 全一致。

## 8. 性能说明
QPS≈550、P50 偏高，主因：单机 Tomcat 默认线程数(200) + 瞬时全量请求 + Micrometer 链路埋点开销。调大线程/降采样/水平扩容可提升。

## 9. 关键 Redis 键
`seckill:stock:{id}`、`seckill:user:{id}:{uid}`、`seckill:limit:{uid}`、`seckill:stream`（组 `seckill-group`）。
